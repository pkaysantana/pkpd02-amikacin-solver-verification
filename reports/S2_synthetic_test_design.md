# PKPD-02 S-2 — Synthetic Estimation-Test Design (PROPOSED; not approved, not run)

**Date:** 30 October 2026 · **Status:** design for review. **No fit of any kind (synthetic or real) has been performed**; fitting synthetic data is a future implementation activity that needs its own approval (v1.1 §7 step 2). Thresholds below are proposed pre-declarations; they are not frozen and must not be tuned after results are seen.

**Naming.** v1.1 §3 uses "S-2" for the forecast-engine test (closed-form superposition vs an independent ODE, ≥ 1,000 randomised histories). This design covers fit-schema inspection and synthetic estimation. I propose **S-2a** = forecast-engine test (v1.1 wording, to be re-pointed at the explicit-ODE engine per amendment C-1) and **S-2b** = the tests below. S-2a is not designed here beyond noting that `tests/s2prep_canonical_equivalence.R` already supplies randomised histories with resets that a larger S-2a can reuse.

## 0. Static findings that shape the design (`evidence/s2_static_schema_inspection.json`)

- nlmixr2's own ODE/sensitivity tolerances are atol 1e-6, rtol 1e-3 (also `atolSens`, `rtolSens`); tolerances can only be set through `foceiControl(rxControl = rxControl(...))`; top-level `atol=` is rejected.
- In a pilot solve of the compiled inner model (not a fit; 32 synthetic patients, 915 rows) sensitivity states `∂Ac/∂η` had scaled error 3.1e-3 at nlmixr2 defaults and ≈ 1.9e-7 for 1e-8 and tighter; the latter is the noise floor of the **finite-difference** reference, so exact reference gradients are needed (T-G).
- The default covariance fallback chain `r,s → r → s` conflicts with C4; `covFallback = list()` is accepted by the control object (effect on a fit unverified).
- Omega is optimised on a `sqrt` coordinate by default (`diagXform`); the coordinate of any returned covariance is unverified. `boundTol` (0.05) is an estimation-scale distance, relevant to C8.
- Solve cost per function evaluation is small (≈ 0.01 s per 32 patients), but full FOCEI runtime is unknown.

## 1. Common design

| Element | Specification (proposed) |
|---|---|
| Data | **Synthetic only**, generated by a seeded generator separate from any empirical code path (L10). Event tables follow the canonical representation (episode-relative clock, patient-level offset table, EVID=2 covariate rows) and include time-varying CRCA/AJBW, 0.5 h and non-0.5 h infusions, sample/dose ties, and multi-episode patients sharing patient-level η. |
| Truths | **D1:** 1C truth. **D2:** 2C truth with well-supported Q, V2. **D3:** 2C truth with weakly identifiable Q/V2 (expected to fail C2/C5–C7; tests that the gates fail closed). |
| Size | N = 100 synthetic patients per dataset with sparse sampling resembling the real design in counts only; R = 50 replicates per truth. Seeds: base 20261201 + replicate index (declared, logged per fit). |
| Fits | Both models fitted to every dataset, same covariates and `combined2`; start values from a fixed rule not using the truth. |
| Records | Every attempt kept (success code, warnings, OFV, runtime, tolerances in effect from the **fit object**), nothing dropped; failed fits count as failures. |

## 2. Tests

| ID | Question | Method | Proposed acceptance |
|---|---|---|---|
| **T-P** pathway/schema | Does the fit object prove the explicit ODE ran? | From each fit object assert: stored model has no `linCmt` flag (−100) and states `Ac`(/`Ap`); `atol`, `rtol`, `covsInterpolation` accessors equal the requested values; `covFallback` as requested | 100% of fits; any mismatch invalidates the run |
| **T-G** gradient accuracy | Are inner sensitivities and outer gradients accurate? | Exact reference sensitivities from the **augmented matrix-exponential** (extend the base-R reference with ∂M/∂η per interval), at tolerance configs {nlmixr2 default, state 1e-10 + sens default, all 1e-8, 1e-10, 1e-12}. Outer gradient: compare nlmixr2's gradient at the truth with an independent exact-gradient FOCEI objective evaluated by the reference | scaled error ≤ 1e-6 at the production config on every row; the nlmixr2-default config must **fail**, demonstrating test power |
| **T-R** parameter recovery | Is the estimator unbiased enough in identifiable settings? | D1/D2 replicates: median bias of log θ (CL, V; Q, V2 for 2C) and of residual SDs; 95% Wald coverage from the verified named covariance | \|median bias\| ≤ 0.10 (CL, V, SDs) and ≤ 0.20 (Q, V2, ω²) in log; coverage within 0.88–0.99 (50 reps ⇒ wide; reported, not tuned) |
| **T-C** covariance stability | Is the named, PD, non-fallback covariance reliable? | Compare `r,s` vs `r` vs `s`; ratio of mean Wald SE to empirical SD across replicates; condition number; PD fraction; confirm that with `covFallback = list()` a failure is visible (no silent method switch). Verify the coordinate transform to `ξ = log(θ, σ)` by finite-difference Jacobian against the documented coordinates (needed for U2) | PD fraction ≥ 0.9 on D1/D2; SE/SD ratio median in 0.8–1.25; Jacobian error ≤ 1e-6; zero silent fallbacks |
| **T-T** tolerance sensitivity | Which ODE and sensitivity tolerances are adequate? | Refit the same datasets and starts at the T-G configs | \|ΔOFV\| ≤ 0.01 and max \|Δlog θ\| ≤ 0.01 vs the 1e-12 reference config; the loosest config meeting this with ≥ 10× margin becomes the production proposal (declared in an amendment, not here) |
| **T-V** convergence/multi-start | Does the R0/R1/R2 ladder behave and do C1/C2 detect trouble? | v1.1 ladder on 20 datasets per truth; apply C1–C9 exactly as written | D1/D2 pass rate and D3 failure rate reported; **no threshold changes after seeing results** |
| **T-RT** runtime | Is the planned workload feasible? | Wall time and memory per fit at the production config (1C, 2C, N ≈ 80 training patients); extrapolate to 5 folds × 2 models × ladder (worst case 63 starts ⇒ 630 fits) | proposed budget: median ≤ 2 min per fit (≈ ≤ 21 h sequential worst case); otherwise a pre-declared reduction/parallelisation amendment, not an ad-hoc cut |
| **T-H** hygiene | Are synthetic and empirical paths separated and results reproducible? | Same seed ⇒ identical fit hash; no import of empirical files in S-2b scripts (static check); L3-style invariance on synthetic folds (altering held-out synthetic concentrations leaves the training fit unchanged) | all pass |

## 3. Prerequisite code changes (proposed; none implemented here)

1. Encode v1.1 bounds as log-scale `ini()` bounds (accepted; shown in `s2_static_schema_inspection.json`).
2. Build model specifications and `foceiControl(rxControl = rxControl(atol, rtol, atolSens, rtolSens, covsInterpolation = "locf"), covFallback = list())` in one guarded constructor that refuses any other route.
3. Add exact-sensitivity reference (augmented matrix exponential) for T-G.
4. Implement extraction functions for C1, C4–C9, U2 with unit tests against fit objects; they must **fail the stage** (not skip a check) when a field or coordinate is unavailable (v1.1 §4).
5. Add the fit-object pathway assertion (T-P) and a seeded synthetic data generator in a directory that cannot read empirical data.

## 4. Risks and decisions needed

- Approval to run any synthetic fit (v1.1 §7 step 2).
- Whether T-RT's runtime budget is acceptable on this WSL2 machine; ODE-based FOCEI with sensitivities may be slower than analytic `linCmt()`.
- D3's expected failure is a **hypothesis**; if D3 passes C-gates the weak-identifiability design needs revisiting before it is used as evidence of fail-closed behaviour.
- The 20% ambiguity rule (Gate A) is separate from these tests.
